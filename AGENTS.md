# LiteLLM Spend: работа с проектом

- Отвечай и пиши новую документацию по-русски. Начни с `docs/architecture.md`.
- Репозиторий `serge-masiutin/litellm-spend-desktop` должен оставаться приватным.
  Не публикуй releases, приложение или секреты без отдельного запроса.
- Не меняй рабочую установку, LaunchAgents и данные при разработке или сборке.
  Не перезапускай службу OpenCode из активной сессии.
- Сохраняй привычную компоновку панели. Новые окна настройки не требуют её редизайна.
- Расход ключа получай из заголовков ответов LiteLLM. Не делай запросы к моделям
  для проверки бюджета; события других провайдеров не должны попадать в учёт.
- Сохраняй `accountingVersion: 2`, UTC-сброс и формулу кеша из `docs/architecture.md`.
- Telegram показывает все текущие и максимум четыре недавних сессии; алерты —
  до десяти критических в одном сообщении. Не включай автоматическую отправку
  при сохранённом `enabled: false`, не отправляй живые тестовые сообщения сам.
- Не копируй `config.json`, ключи, токены, пользовательские записи или `.git/gh`
  в исходники, bundle и коммиты. Упаковку веди по allowlist в `desktop/build.sh`.
- Перед изменением прочитай вызовы и тесты; отделяй адаптеры от ядра.
  Для контрактов и тестов применяй `maintainable-code`, для TS-логики — `layered-ts`,
  для API OpenCode — `opencode`, для текстов — `clear-writing`, если они доступны.
- Проверки: `bun run check`; затем `bun run build` и `bun run smoke` для desktop.
  Smoke использует временные данные, без сети. Типы host SDK OpenCode этим набором
  не проверяются. Готовую `.app` не перезаписывай; укажи другой путь сборки.
- Коммить только явные пути. Не меняй глобальные Git/SSH и авторизацию других проектов.
  В отчёте отделяй пройденные проверки от непроверенного.
